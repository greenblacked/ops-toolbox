- The RouterOS release watcher no longer regenerates a bump pull request that
  a maintainer closed without merging: the existing-PR check now looks at open,
  merged and closed pull requests for `deps/routeros-<version>`. A declined
  version cannot be regenerated by the watcher, even by a manual run with
  `version` set; reopen its pull request and update it from `dev`, or wait for
  the next release. A failed candidate's issue now carries the
  `routeros-candidate-failure` label, and only an open, labelled issue filed
  by the Actions bot suppresses the bump, so an issue anyone else opens with
  the same title can no longer switch the watcher off; the lookup reads only
  labelled issues instead of the newest 100 open ones, and a failure is still
  recorded when the label cannot be created. The workflow dispatch moved to
  its own job holding only `actions: write`, so the job that runs
  `routeros_version.py` and `run-tests.sh` from `dev` no longer has that
  scope. An open failure issue filed before this change has no label, so
  label it `routeros-candidate-failure` by hand or the next poll retests that
  version once.
- `mikrotik/README.md` and `security.yml` described the watcher as running on
  Mondays and Thursdays; it runs every six hours.
